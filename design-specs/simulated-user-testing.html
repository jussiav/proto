Research method · tooling

Simulated user testing

An AI-played persona with no product knowledge drives a real browser against the prototype, decides each step from what the screen says, and writes a report. It finds product issues in a day and for a fraction of a human study — and it is heuristic evidence, meant to be validated with real sellers rather than to replace them.

Method in use · 14 participants run, September 2026 Simulated, not human

What it is for

Find product issues early

Where a seller hesitates, misreads a label, or acts before reading the thing we built for them. Cheap enough to run on a design before it is worth a human study.

Compare two designs

Paired participants — same persona, same device, same seed, one variable changed. That pairing is what makes a difference readable at all.

Prepare the human study

The same tasks, seeded state and probes can be handed to real sellers afterwards, so the two sets of findings can be compared rather than guessed at.

Every participant is an AI persona, not a person. Findings are heuristic. The attention findings — what was on screen, what was scrolled past — transfer best, because they depend on layout rather than on the persona having a plausible inner life.

How a run works

The persona reads a page, decides in character, acts, and reads the result. Those decisions are made by a model between the steps, so each step is a separate process — which is why this needs a driver rather than a script.

The driver

Chrome is launched detached with a debugging port, and every command reconnects over CDP and disconnects. The page, localStorage, an open modal and a half-typed counter-offer survive between the model’s decisions.

node ut.cjs start p1 9301 desktop "…/index.html?mode=test"
node ut.cjs state p1
node ut.cjs do    p1 '[{"click":"text=Jatka"}]'
node ut.cjs event p1 new-offers
node ut.cjs stop  p1

What is scripted, and what is not

  • Scripted: the backend. Photos arrive, the auction goes live, offers land, a dealership replies or closes the negotiation.
  • Scripted: the starting state. A finished listing can be seeded so a study of one surface does not have to walk the funnel.
  • Free choice: everything the seller does. Accept, counter-offer, reject, give up, or decide without scrolling to the argument.

Run shapes, and what they cost

Cost is driven by the number of commands, not the size of any one: every result stays in the runner’s context for the rest of the run, so call 90 pays for calls 1–89 again.

Shape Use when Commands Tokens
End to end Expectations built across the journey, or a handover between steps 89–124 271k–338k
Partial One surface. Seed the rest, keep the step that produces the input it depends on 33–64 197k–248k

What made it cheaper

  • state returns headings, interactive elements and trimmed content — not a full text dump of nav, FAQ and footer.
  • do runs a whole step in one command instead of one per field.
  • Seeding past what is not being tested, and ending the run at the first real decision. Roughly a 40% cut.

What did not

Telling the runner to use fewer commands. A stated ceiling of 45 produced runs of 33 to 64 — agents self-regulate to the task and treat the number as advisory. Removing work is the only lever that held.

Screenshots are effectively free: written to disk, never read back.

Known weaknesses

Stated plainly, so nothing from a simulated batch gets quoted as more than it is.

Measurements need verifying centrally

Agent-reported pixel positions were wrong in two of three cases, both understating the problem. Any layout claim is re-measured before it reaches a report.

Persona consistency bias

A sharply written character sheet tends to come back as the finding. Belief is written as a starting position — “he has seen listings at X” — not as an identity.

Self-reported causality is soft

“That line changed my mind” is the model narrating itself. Behaviour — what was scrolled, typed, clicked — is the part worth trusting.

One observation per cell

A six-participant batch is n=1 per cell unless participants were paired on purpose. Thresholds from it are hypotheses, never measurements.

Open questions for review

  • Should state diff against the previous state and return only what changed? That is the next cut and it is not built.
  • Should seeding, world events and assertions become a library that the scripted smoke test uses too? The two duplicate the notion of a scenario today.
  • Should the driver move to a shared package for other prototypes? Its only AutoVex-specific parts are seed and event.
