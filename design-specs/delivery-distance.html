Toimitusmatka — delivery distance selector

The delivery-distance question in details.html was rebuilt from a range slider into option cards with a free-distance fallback. This page is the single reference for the change: rationale, behavior, states, data contract and copy.

Status: implemented Page: details.html Data key: details.deliveryRange August 2026

1 · Previous design and its issues

Removed UI (inert replica)

Tarjoukset alueesi ulkopuolelta sisältävät noudon kotipihastasi

325 km

Issues

  • Preselected default (325 km). Sellers could pass the question without ever considering it. In the data, a deliberate 325 and an untouched default were indistinguishable.
  • No consequences shown. Nothing told the seller what the value does in the auction — that offers from outside the range include dealer pick-up, or that a wider range attracts more offers without pick-up and typically a higher price.
  • False precision. 25 km steps on a 50–600 range imply differences that don't exist, and sliders are hard to set precisely on mobile.
  • No "anywhere in Finland". The 600 km cap was arbitrary; the strongest option for the auction could not be expressed at all.
  • Weak framing. A question + an unanchored number gave the seller no reference points to reason from.

Why this behaves better

  • The consequence is the content. Every option pairs a distance with what it means in the auction: how far the seller drives themselves, whether dealers will pick the car up, and that a wider range means more offers without pick-up — and typically a higher price. The seller decides on outcomes, not on an abstract number of kilometres.
  • Offers outside the range still come. The helper text makes the core promise explicit: the listing is visible to every dealer in Finland regardless of the choice; dealers outside the range include home pick-up and price its cost into their offer. Choosing a short distance no longer feels like shrinking the auction.
  • No default. Nothing is preselected, so every stored value is a deliberate answer. The data becomes trustworthy for pricing and matching.
  • One tap for most sellers. Four presets in descending order cover the realistic cases; typing is needed only for the rare in-between value.
  • "Minne vain Suomessa" hides the number. The strongest option is a promise, not a radius — it stores 500 without showing it.
  • Native radios. Keyboard and screen-reader behavior come from the platform, matching every other card group in the funnel.

Behavior (exact, from concept 8) + what changed

  • No default. Field is empty; − starts disabled (nothing to step down from), the first tap of + sets the value to 50 km.
  • Steps of 50 km. − disables at 50 (and when empty), + disables at 500.
  • New: the range is visible before the seller hits it. The empty field reads 50–500 as its placeholder (same pattern as the custom field in the primary candidate), so the allowed range is on screen from the start. It answers "why 50–500?" without stating the business reasoning, and the auto-correction message no longer appears out of nowhere.
  • Free typing allowed. While typing, the raw value is kept. On blur the value is rounded to 10 km precision and clamped to 50–500; out-of-range entries get the neutral grey correction message, not an error.
  • Empty field = no value. Unlike the primary candidate, an empty field is not an in-field error — the page-level continue validation catches it with the standard required-field message Pakollinen kenttä. (err.required), not the choice-oriented Valitse yksi vaihtoehto. the option cards use.
  • New: fixed impact block. Three constant lines under the field explain the consequence of the distance: dealers within it can offer without pickup, dealers beyond it collect the car and price the pickup into their offer, and the listing is visible to all dealers in Finland regardless. The block never changes with the value — nothing to probe by trying different numbers (implementation rule 8 of the exploration).
  • Why still secondary: typing/stepping gives no anchor points — the option cards name realistic scenarios and pair each with its outcome in one tap. This variant suits an A/B test arm or compact layouts.

4 · Behavior rules

  1. No default value. Nothing preselected, nothing prefilled — ever.
  2. Selecting "Muu etäisyys" with an empty field is an immediate error. The field enters error state on the same tap, so a missing value can't survive to the bottom of the form unnoticed.
  3. Values below 50 or above 500 are auto-corrected on blur. The message is neutral grey, not red — the user made no mistake; the value was moved into the allowed range.
  4. Free input is rounded to 10 km precision on blur (e.g. 275 → 280), silently when the value was already in range.
  5. Typing in or focusing the field selects "Muu etäisyys"; picking a preset clears the field. Two values can never be active at once.
  6. No continue button inside the component. Validation happens in the field because the page's submit button is far below.
  7. Preset click / field input also clears the page-level "select one" error if the continue button had flagged the group.

5 · Data contract

Aspect Rule
Stored fieldOne integer only. Prototype: details.deliveryRange (localStorage draft). Production equivalent: delivery_radius_km. No flags, no extra fields.
Range50–500 km after blur. While typing, the raw value is held; blur clamps and rounds.
Preset values500 · 300 · 100 · 50 — each stores exactly the number shown on the card. "Minne vain Suomessa" shows no number to the user but stores 500.
Custom valuesRounded to 10 km precision, clamped to 50–500.
Empty / untouchedStored as empty — blocks the page-level continue validation like any other required field.
DownstreamSummary card/modal renders the raw number as "N km". No consumer changes were needed.

6 · Guardrails — deliberate omissions

  • No dealer counts. The options never claim "N dealers in your area" — every dealer in Finland sees the listing regardless of the choice.
  • No value-dependent extra info under the selector. If the UI reveals different content per value, users start probing values to see what appears. The helper text is fixed.
  • No default — restated because it is the most tempting regression. A preselected option reintroduces the exact data-quality problem this change removes.

8 · Rejected / deferred alternatives

Number field with ± 50 km steppers (promoted)

Originally rejected for typing friction and missing anchor points. Revived as the secondary candidate (section 2b) with a fixed impact block that explains the consequences the original lacked.

Coarse band → refine chips

Rejected. Two taps instead of one, and chips have no room for the consequence copy — the one thing this question must communicate.

Real place names as options (phase 2)

Deferred. "Helsinki, Turku, Vaasa" is more concrete than kilometres and hints at the return trip, but requires distance computation from the seller's postal code plus fallbacks for sparse regions. Structure is identical to the shipped version, so a later A/B directly prices the data integration.

Finland map visualization (phase 2)

Deferred. The only variant where the core promise is a picture — the whole country is always colored, only the shade changes. Needs a ZIP centroid and a vector map; a radius is also as-the-crow-flies, not driving distance.
